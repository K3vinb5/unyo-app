# Unyo Agent Guide

## Build & Codegen

```sh
flutter pub get
flutter pub run build_runner build --delete-conflicting-outputs
flutter build linux --release
../unyo-lib/installJRERelease.sh linux   # copy the custom built JRE into the release bundle (CI does this on prod). Debug bundles get it automatically via the CMake symlink — no manual step
```

**Always run `build_runner` after `flutter pub get`** or after modifying any files using code generation (freezed, json_serializable, hive_ce_generator, auto_route). Do NOT manually edit `*.g.dart` files — they are generated.

**Exception:** `lib/generated/json/**` is NOT handled by `build_runner`. It is generated by **fjson-cli** (sibling repo `../fjson-cli`, replaces the old FlutterJsonBeanFactory IntelliJ plugin):
- New entity from JSON: `java -jar ../fjson-cli/build/libs/fjson-cli.jar bean --class MyQuery --file payload.json --output lib/core/services/api/dto/<source>/ --set-default --project .`
- Regenerate helpers after editing any `@JsonSerializable` DTO: `java -jar ../fjson-cli/build/libs/fjson-cli.jar gen --project .`
- DTO style rule: all fields keep `late` and non-primitive fields must be eagerly initialized (`late Foo foo = Foo();`) for null-safety against missing API keys.

## Git

Commit message convention (see `git log`): lowercase type prefix, a colon, then a short imperative description.

- `rewrite: ...` — the default for most changes (features, refactors, behavior changes)
- `fix: ...` — bug fixes
- `docs: ...` — documentation-only changes

Examples: `rewrite: Added a factory pattern for episode metadata services`, `fix: make AppImage entrypoint executable`.

Rules:
- **Default to a PR — never ask.** For each commit you plan to create, and for each commit already sitting locally: unless the user explicitly said to push directly in that request, put the commit on a feature branch, push it, and open a PR against `rewrite` (the active integration branch) with `gh pr create`, then hand back the PR URL. Never merge it yourself, and never pause to ask — the silent PR default is what keeps long sessions moving. Direct push to `rewrite`/`master` only when explicitly requested.
- Always check `git log --oneline -20` before committing to confirm the current convention.
- Do not commit `lib/generated/json/**` or other `*.g.dart` changes separately from the source change that caused them — regenerate and include them in the same commit.
- Never commit throwaway test entities/scratch files.

## Architecture

- **Flutter desktop app** (Linux, Windows, macOS) — anime streaming & manga reader
- **State**: BLoC (`flutter_bloc` + `rxdart`)
- **DI**: `get_it` via `lib/core/di/locator.dart`
- **Codegen tools**: `freezed`, `json_serializable`, `hive_ce_generator`, `auto_route`, `auto_route_generator`
- **Key generated files**: `*.g.dart` (Hive, Freezed, JSON), `lib/generated/json/*.g.dart`, `lib/hive_registrar.g.dart`
- **External Go binding**: The torrent server (`libmtorrentserver`) is built from `go/binding/desktop/` — cloned separately; must be compiled per-platform as a c-shared library

## Dependencies

- `unyo_lib` is a local path dependency (`../unyo_lib`). Ensure it exists as a sibling directory.
- Local extensions require **Java 17+** installed.

## Flutter Version

Pinned to **3.47.7** (see `.fvmrc`). Use `fvm flutter` if managing multiple versions.

## Release Process

Releases are triggered by **git tags**. The CI workflow (`main.yml`) builds Go bindings for all three platforms, then runs the Flutter build. Do not manually edit generated `.g.dart` files before a release tag.

## Shared Knowledge (unyo-docs)

Cross-project knowledge lives in the sibling repo `../unyo-docs`
(https://gitea.k3vinb5.dev/Unyo/unyo-docs). When a task spans multiple unyo
repos, or you're stuck on tooling/environment, scan `../unyo-docs/INDEX.md`
first and read only what's relevant. When you discover a hard-won, non-obvious
fact, add it following the rules in `../unyo-docs/README.md` — brevity over
completeness; repo-specific facts stay in this file.
